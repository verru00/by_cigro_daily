# cigro 데일리 리프레시 (주문 + 광고)

두 개의 독립된 워크플로가 돈다.

| | 워크플로 | 진입점 | 수집 기간 |
|---|---|---|---|
| 주문(매출) | `cigro_refresh.yml` | `src.main` | 전전월 1일 ~ 어제 |
| 광고(캠페인) | `cigro_ads_refresh.yml` | `src.ads_main` | 어제 하루 (월요일만 이틀) |

아래는 주문 리프레시 문서다. 광고는 맨 아래 [광고(캠페인) 데일리 리프레시](#광고캠페인-데일리-리프레시) 참고.

---

## 주문내역 데일리 리프레시

cigro.io 주문서 화면의 엑셀을 브랜드별로 자동 다운로드해 구글 시트에 덮어쓴다.

## 동작

```
로그인 → 데이터 아이콘 → 주문 화면 → 주문 카테고리
      → [브랜드 선택 → 기간 설정 → 엑셀 다운로드] × 브랜드 수
      → 구글 시트 탭별 전량 덮어쓰기 → Google Chat 알림
```

- **수집 기간**: 당월 기준 전전월 1일 ~ 어제 (KST)
  - 2026-08-06 실행 시 → `2026-06-01 ~ 2026-08-05`
- **시트 반영**: 탭 전체를 비우고 재기록. 취소·반품이 소급 반영되므로 증분 append 를 쓰지 않는다.
- **탭 이름**: `주문_{브랜드명}` (예: `주문_코즈코즈`, `주문_수면공감`)

## Secrets

| 이름 | 설명 |
|---|---|
| `CIGRO_EMAIL` | cigro 로그인 이메일 |
| `CIGRO_PASSWORD` | cigro 비밀번호 |
| `CIGRO_SHEET_ID` | 대상 구글 시트 ID |
| `DRIVE_FOLDER_ID` | 원본 엑셀 보관 폴더 ID (비우면 생략) |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스 계정 JSON 전문 |
| `GOOGLE_CHAT_WEBHOOK_URL` | 알림 웹훅 |

## Variables

| 이름 | 예시 |
|---|---|
| `CIGRO_BRANDS` | `코즈코즈,수면공감,포즈업` |
| `DRIVE_KEEP_HISTORY` | `false` (기본) / `true` |

브랜드는 실행 시 입력으로도 덮어쓸 수 있다. 이름은 cigro 드롭다운 표기와 **정확히 일치**해야 한다
(`코즈코즈` 와 `코즈코즈_오늘의집` 은 다른 항목).

서비스 계정 이메일을 대상 시트에 **편집자**로 공유해야 한다.

## 안전장치

| 상황 | 동작 |
|---|---|
| 다운로드 0행 | 시트 미반영, 알림만 |
| 직전 대비 행수 50% 미만 | 시트 미반영, 알림만 (`SHRINK_GUARD` 로 조정) |
| 브랜드 선택 실패 | 해당 브랜드 건너뜀 + 스크린샷 저장 |
| 기간 설정 실패 | 해당 브랜드 건너뜀 (잘못된 기간 수집 방지) |

급감이 실제 상황이라면 `force_write=true` 로 재실행한다.
실패 시 스크린샷과 원본 파일은 artifact 로 90일 보관된다.

## 출력 경로

두 곳에 동시에 나간다.

### 1) 구글 시트 (가공 데이터)

`CIGRO_SHEET_ID` 시트의 `주문_{브랜드}` 탭에 전량 덮어쓰기.
시트 ID 는 URL 에서 가져온다.

```
https://docs.google.com/spreadsheets/d/{여기가_시트_ID}/edit
```

탭 이름 접두어는 `TAB_PREFIX` 로 바꾼다. (`주문_` → `cigro_매출_` 등)

### 2) 구글 드라이브 (원본 엑셀)

`DRIVE_FOLDER_ID` 폴더에 cigro 가 내려준 엑셀 원본을 보관.
폴더 ID 도 URL 에서 가져온다.

```
https://drive.google.com/drive/folders/{여기가_폴더_ID}
```

| 설정 | 동작 | 파일명 예시 |
|---|---|---|
| `DRIVE_KEEP_HISTORY=false` (기본) | 같은 파일을 덮어씀. 공유 링크 유지 | `cigro_주문_코즈코즈.xlsx` |
| `DRIVE_KEEP_HISTORY=true` | 실행일별로 파일이 쌓임 | `cigro_주문_코즈코즈_20260806.xlsx` |

`DRIVE_FOLDER_ID` 를 비워두면 드라이브 업로드를 건너뛴다.
드라이브 업로드는 **시트 반영에 성공한 브랜드만** 수행한다 (두 곳의 내용이 항상 일치).

### 권한

서비스 계정 이메일(`...@....iam.gserviceaccount.com`)을 **양쪽 모두**에 공유해야 한다.

- 대상 시트 → 편집자
- 대상 폴더 → 편집자

> **주의**: 내 드라이브 폴더에 업로드하면 파일 소유자가 서비스 계정이 된다.
> 서비스 계정은 저장 용량 할당량이 없어 `storageQuotaExceeded` 오류가 날 수 있고,
> 나중에 사람이 파일을 지우거나 옮기기 어렵다.
> **공유 드라이브(Shared Drive)** 에 폴더를 두고 서비스 계정을 멤버로 추가하는 방식을 권장한다.

## 실행

수동: Actions 탭 → `cigro_daily_refresh` → Run workflow

정기: **GitHub cron 을 쓰지 않는다.** Apps Script 가 정해진 시각에
`workflow_dispatch` 를 슈팅하고 GitHub 은 실행만 담당한다.
(기존 코즈코즈 자동화와 동일한 구조)

### Apps Script 설정

`apps_script/cigro_trigger.gs` 를 새 프로젝트에 붙여넣는다.

1. 프로젝트 설정 → 시간대 **(GMT+09:00) 서울**
2. 스크립트 속성 등록

   | 키 | 값 |
   |---|---|
   | `GH_TOKEN` | GitHub PAT |
   | `GH_OWNER` | 레포 소유자 |
   | `GH_REPO` | 레포 이름 |
   | `GOOGLE_CHAT_WEBHOOK_URL` | 실패 알림 웹훅 |

3. `setupTriggers` 1회 실행 → 매일 09:30 전후 자동 슈팅

PAT 권한은 fine-grained 기준 **Actions: Read and write**, classic 기준 `repo` + `workflow`.

### 실행 시각

기본 09:30 (KST). cigro 는 각 채널에서 데이터를 수집해 오므로 전일 데이터가
확정되기 전에 돌리면 누락이 생긴다. 화면 상단 "데이터 수집 현황" 을 며칠 관찰해
수집 완료 시각을 확인한 뒤 `RUN_HOUR` / `RUN_MINUTE` 를 조정한다.

Apps Script 시간 트리거는 지정 시각 ±15분 오차가 있다. 분 단위 정밀도가 필요하면
`nearMinute` 대신 매일 일회성 트리거를 재생성하는 방식으로 바꿔야 한다.

### 무음 실패 감지

워크플로 자체가 죽으면(의존성 설치 실패, 타임아웃 등) 파이썬 알림이 아예 나가지 않는다.
그래서 슈팅 25분 뒤 `verifyLastRun` 이 실행 결과를 확인하고,
실패했거나 아직 진행 중이면 Google Chat 으로 알린다.

정상 완료 시에는 워크플로가 이미 상세 알림을 보내므로 중복 발송하지 않는다.

## 첫 실행 순서

1. Secrets / Variables 등록
2. Actions 에서 `dry_run=true` 수동 실행 → artifact CSV 행수·컬럼 확인
3. 정상이면 `dry_run=false` 로 실행 → 시트 확인
4. Apps Script 속성 등록 후 `dispatchCigroDryRun` 으로 슈팅 연결 테스트
5. `setupTriggers` 실행

## 알려진 취약점

cigro 는 Bubble.io 로 만들어진 앱이라 클래스명(`button.coeaXaE0` 등)이 자동 생성된다.
cigro 가 화면을 재배포하면 셀렉터가 바뀌어 스크립트가 깨질 수 있다.
그때는 브라우저 개발자도구로 새 클래스명을 확인해 `src/cigro_scraper.py` 상단 셀렉터를 교체한다.

셀렉터 위치:

| 대상 | 셀렉터 |
|---|---|
| 이메일 / 비밀번호 | `input[type=email][placeholder=E-mail]` / `input[type=password][placeholder=Password]` |
| 로그인 버튼 | `.cnaNaCaF0` |
| 데이터 아이콘 | `.cneaWaH1` |
| 주문 카테고리 | `div.cneaWk1` |
| 브랜드 드롭다운 행 | `div.cnbaFt1` |
| 날짜 OK | `button.coaOys` |
| 엑셀 다운로드 | `button.coeaXaE0` |

# 광고(캠페인) 데일리 리프레시

cigro **분석 > 광고 > 캠페인** 화면의 엑셀을 매일 받아 `광고 RAW` 탭에 병합한다.
주문 리프레시와 분리된 워크플로이며, 로그인 정보와 드라이브 설정만 공유한다.

## 동작

```
로그인 -> [캠페인 화면 URL 직행(하루) -> EXCEL 다운로드] × 수집 날짜 수
      -> 수집일자 찍어서 A~N 병합 -> Google Chat 알림
```

## 화면 진입

URL 파라미터만으로 직행한다. 클릭 탐색이 없어 셀렉터 의존도가 낮다.

```
https://app.cigro.io/?menu=analysis&tab=ad&group_by=campaign
    &brand_name=코즈코즈&start_date=2026-09-10&end_date=2026-09-10
```

| 파라미터 | 값 | 의미 |
|---|---|---|
| `menu` | `analysis` | 분석 |
| `tab` | `ad` | 광고 |
| `group_by` | `campaign` | 캠페인 (`ad_channel` 이면 광고채널) |
| `brand_name` | `코즈코즈` | 브랜드. 드롭다운 클릭 불필요 |

화면에 표시된 기간을 읽어 URL 이 실제로 먹혔는지 검증하고, 다르면 달력을
직접 클릭한다. (주문 화면은 URL 날짜를 '오늘-30일'로 덮어썼던 전력이 있다)

## 수집 날짜 — 하루씩 따로 받는다

**중요**: 이 화면은 선택한 기간을 **합산**해서 캠페인당 1행으로 보여준다.
표에 날짜 열이 없다. 이틀치를 한 번에 받으면 두 날이 하나로 합쳐진다.

그래서 **날짜마다 따로 다운로드**하고, 시트 A열 `수집일자`에 그 날짜를 찍는다.

| 실행 요일 | 수집 날짜 | 다운로드 횟수 |
|---|---|---|
| 화~토 | 전일 | 1회 |
| **월** | **전전일, 전일** | **2회** |
| 일 | 전일 | 1회 (돌려도 무해) |

예) 월요일 `2026-09-14` 실행 -> `2026-09-12` 1회 + `2026-09-13` 1회

일요일을 건너뛰어도 누락되는 날이 없다 (100일 시뮬레이션 검증).
일요일에도 돌리면 토요일만 재수집되는데, 날짜 기준 교체라 결과는 같다.

## 시트 반영 — `광고 RAW`

주문 시트와 같은 방식이다. **A~N 만 관리하고 O~V 는 건드리지 않는다.**

| 범위 | 내용 | 자동화 |
|---|---|---|
| A | `수집일자` | **파이썬이 찍음** (엑셀에 없는 값) |
| B~N | `광고채널 캠페인 광고비 노출수 클릭수 전환수 전환값 CPM CTR CPC CPA CPI ROAS` | 엑셀에서 매핑 |
| O~R | `셀러명 셀러ID 상품분류 구분(공구여부)` | 손대지 않음 |
| S~V | `년 월 주 일` | 손대지 않음 (수식) |

전량 덮어쓰기가 아니라 **수집한 날짜의 행만 교체**한다. 과거 데이터는 보존.
기록 후 A열 기준 오름차순 정렬. 앞부분이 동일하면 그만큼 기록을 생략한다.

S~V 가 ARRAYFORMULA 가 아니라 행마다 들어가는 수식이라면
`ADS_FILL_FORMULAS=true` 로 두면 신규 행에도 파이썬이 채워준다.

## Secrets

주문 리프레시와 대부분 공유한다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `CIGRO_EMAIL` / `CIGRO_PASSWORD` | O | 주문과 공유 |
| `CIGRO_SHEET_ID` | O | `광고 RAW` 가 있는 시트 (주문과 같은 시트) |
| `CIGRO_ADS_SHEET_ID` | | 광고를 **다른 시트**에 쓸 때만 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | O | 주문과 공유 |
| `DRIVE_FOLDER_ID` | | 원본 엑셀 보관 (비우면 생략) |
| `GOOGLE_CHAT_WEBHOOK_URL` | | 알림 |

## Variables

전부 기본값이 있어서 **아무것도 등록하지 않아도 동작한다.**

| 이름 | 기본값 | 설명 |
|---|---|---|
| `ADS_SHEET_TAB` | `광고 RAW` | 기록할 탭 |
| `CIGRO_AD_BRAND` | `코즈코즈` | URL `brand_name` |
| `ADS_GROUP_BY` | `campaign` | URL `group_by` |
| `ADS_FILL_FORMULAS` | `false` | 신규 행에 S~V 수식 채우기 |
| `CIGRO_ADS_URL` | (빈값) | URL 통째 교체. `{s}` `{e}` `{b}` 치환 |
| `ADS_EXCEL_SELECTOR` | (빈값) | EXCEL 버튼 셀렉터 |

`광고 RAW` 에는 **브랜드 열이 없다** = 단일 브랜드 전용 탭이다.
여러 브랜드를 한 탭에 넣으려면 시트에 브랜드 열을 먼저 추가해야 한다.

## 안전장치

| 상황 | 동작 |
|---|---|
| 화면 진입 실패 | 시트 미반영 + 스크린샷·probe 덤프 |
| 기간 불일치 | 시트 미반영 (합산 데이터 유입 방지) |
| 하루라도 다운로드 실패 | **전체 미반영** (부분 반영 시 그 날짜가 비어버림) |
| 수집 0행 | 시트 미반영, 알림만 |
| A열 날짜 절반 이상 파싱 실패 | 시트 미반영 (중복 누적 사고 방지) |
| 엑셀에 없는 시트 열 | 중단 (화면 구성 변경 감지) |
| 병합 결과가 직전의 50% 미만 | 시트 미반영 (`SHRINK_GUARD`) |

날짜 파싱 가드가 중요하다. A열 표시 형식이 예상과 다르면 교체 대상을 하나도
못 골라 같은 날 데이터가 계속 쌓인다. `2026-09-10` `2026. 9. 10` `2026/9/10`
`2026.09.10` 은 모두 흡수하지만, 그래도 절반 이상 못 읽으면 멈추고 알린다.

## 실행

수동: Actions -> `cigro_ads_daily_refresh` -> Run workflow

| 입력 | 용도 |
|---|---|
| `dry_run=true` | 다운로드 + 엑셀 열 목록 확인, 시트 미반영 |
| `probe=true` | 화면 덤프만 (셀렉터가 깨졌을 때) |
| `force_write=true` | 급감 가드 무시 |
| `start_date` / `end_date` | 특정 구간 재수집 (**하루씩 나눠서** 받는다) |

`start_date=2026-09-01`, `end_date=2026-09-05` 로 넣으면 5일치를 하루씩
5번 받아 5일분 행을 채운다. 과거 구멍 메울 때 쓴다.

정기: Apps Script `setupTriggers` 가 주문(09:30)과 광고(10:30) 트리거를
함께 설치한다. 광고를 뒤로 뺀 건 두 워크플로가 동시에 cigro 에 로그인하는
상황을 피하기 위함이다.

**기존에 `setupTriggers` 를 이미 돌렸어도 다시 실행해야** 광고 트리거가 설치된다.

| Apps Script 함수 | 동작 |
|---|---|
| `dispatchCigroAdsRefresh` | 광고 정식 실행 (25분 뒤 결과 검증) |
| `dispatchCigroAdsDryRun` | 광고 dry-run |
| `dispatchCigroAdsProbe` | 광고 화면 덤프 |

## 첫 실행 순서

1. Actions -> `cigro_ads_daily_refresh` -> `dry_run=true` 실행
2. 알림/로그의 **엑셀 열 목록**이 시트 B~N 13열과 일치하는지 확인
3. `dry_run=false` 로 실행 -> `광고 RAW` 탭에서 전일 행 확인
4. Apps Script `setupTriggers` 재실행

실패하면 `probe=true` 로 돌려서 artifact 의 `probe_*.txt` 에서 실제 클래스명을
찾아 `ADS_EXCEL_SELECTOR` 에 넣는다.

## 화면 로딩 대기

Bubble 콜드 로드는 10~20초씩 걸린다. 고정 대기로는 부족해서 준비 신호가
나타날 때까지 폴링한다(최대 75초). 아래 중 **하나라도** 보이면 통과.

1. `button.export-btn` (EXCEL 버튼) — 우리가 실제로 눌러야 하는 것
2. 기간 표시 `YYYY-MM-DD - YYYY-MM-DD`
3. `캠페인` / `광고비` / `ROAS` 중 2개 이상

그래도 안 되면 **새로고침 1회** -> 그래도 안 되면 **사이드바 클릭 경로**로
넘어간다. 세 단계가 다 실패해야 그 날짜를 건너뛴다.

## 확인된 셀렉터

| 대상 | 셀렉터 | 안정성 |
|---|---|---|
| EXCEL 다운로드 | `button.export-btn` | **높음** — Bubble 자동생성 아님 |
| 사이드바 분석 | `div.cnaNaPc2` | 낮음 — 자동생성 |
| 광고 탭 | `div.cnaNaQg2` | 낮음 — 자동생성 |
| 캠페인 탭 | `div.cnoraD3` | 낮음 — 자동생성 |

정상 경로(URL 직행)에서 쓰는 건 **`button.export-btn` 하나뿐**이다.
이 클래스는 자동생성이 아니라 재배포에도 잘 살아남는다.
나머지 셋은 사이드바 클릭 경로(마지막 수단)에서만 쓰이고,
바뀌어도 텍스트(`분석`/`광고`/`캠페인`) 클릭으로 재시도한다.

셀렉터가 깨지면 `probe=true` 로 돌린다. artifact 의 `probe_*.txt` 에
**URL / 페이지 제목 / 본문 텍스트 / 클릭 가능 요소 전체**가 남아서
어느 화면에서 멈췄는지 바로 보인다. 거기서 새 클래스명을 찾아
`ADS_EXCEL_SELECTOR` 에 넣으면 코드 수정 없이 고쳐진다.


## 손익(핵심이익지표) 리프레시

cigro `분석 > 핵심이익지표` 엑셀을 받아 **공헌이익 · 매출이익 · 순이익** 세 탭에 기록한다.

```
python -m src.pnl_main
```

| 항목 | 값 |
|---|---|
| 수집 기간 | 전전월 1일 ~ 어제 (주문과 동일) |
| 다운로드 | 1회 (엑셀 한 파일에 시트 3개) |
| 교체 기준 | 기간 안의 날짜 행만 교체, 나머지 보존 |

### 왜 크롤링하는가

공헌이익과 순이익은 매출·원가만으로 재현할 수 없다.

```
공헌이익 = 매출이익 − 수수료·배송비·광고비 − 변동 판관비
순이익   = 공헌이익 − 고정비
```

변동 판관비와 고정비는 cigro 에 직접 입력되는 값이다.
판관비는 월말·월초에 입력되므로 매일 지난 두 달을 다시 받아
언제 입력되든 다음 실행에서 반영되게 했다.

### 년·월·주·일

시트 헤더에 `년` `월` `주` `일` 칸이 있으면 **파이썬이 값으로 채운다.**
ARRAYFORMULA 는 행이 늘수록 시트 전체를 다시 계산해 느려지기 때문이다.
주차는 구글시트 `WEEKNUM(date, 2)` (월요일 시작) 와 같은 값이 들어간다.

시트 수식으로 관리하려면 `PNL_FILL_DATEPARTS=false` 로 두고
해당 열의 **헤더를 비워두면** 코드가 그 영역을 건드리지 않는다.

### 변동판관비 감시

변동판관비는 월말·월초에 cigro 에 입력된다. 입력 전에는 공헌이익이 과대 표시되므로
그 구간에만 값이 들어왔는지 확인해 알린다.

| 시점 | 대상 월 |
|---|---|
| 말일 3일 전 ~ 말일 | 당월 |
| 익월 1~7일 | 전월 |

기록 **전**의 시트 값과 새로 받은 값을 비교한다.

```
🔎 변동판관비 확인 필요 — 2026-09 변동 없음 (현재 0원)
💰 변동판관비 +2,000,000원 확인 — 2026-09 (현재 2,000,000원)
```

구간은 `PNL_SGA_BEFORE_END` · `PNL_SGA_UNTIL_DAY` 로 조정한다.

### 주의

세 탭 중 하나라도 검증에 실패하면 **나머지도 쓰지 않는다.**
지표 간 시점이 어긋나면 분석이 틀어지기 때문이다.

크롤링 값은 **일자별 총계**라 셀러·상품으로 쪼갤 수 없다.
셀러별 기여도를 보려면 주문·광고 데이터로 따로 계산해야 한다.
